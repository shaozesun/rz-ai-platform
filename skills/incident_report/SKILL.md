# 数据中心事件统计表

以**飞书园区群通报**为入口（不是告警表）：一行 = 一次已通报事件（速报 + 通报配对），关联 DCIM 告警与告警工单，
补全发生时间、地点、事件原因/进展、处理时长与违规判定。

## 工作流

1. 调 `incident_report(shift, date, start, end, parks, sync, export_excel)`。它是一个**确定性工具**：
   班次用 `shift`/`date` 传语义、窗口由服务端算，**不要自己换算时刻**。
   **回答开头先写本次窗口**：复述返回的 `window` 与 `window_note`（归属口径见 `window_basis`），
   例如「以下为白班 2026-10-26 08:30~17:30、按事件发生时间统计；当天 00:00–08:30 的告警属前一晚班」。
   **禁止**把班次窗口说成「今天只有 N 条」—— 用户拿凌晨的告警来对就会以为数据丢了。
2. 按返回里的 `mode` 交付（**不要自己另存文件、不要改写 url**）：
   - `inline`（≤20 条）：**原样输出返回的 `table_markdown`**（服务端按固定列渲染好，
     含日期/发生时间/**速报时间**/**首报时间**/地点/事件类型/事件名称/事件进展/
     过程有无违规及全部有效列，空值已是「—」），再**原样输出 `file_tag`**（同内容的
     交互表格，可搜索/排序/翻页）。表格前后各加一两句结论即可。
     **不要自己重排、合并、增删列，也不要另造一张表** —— 缺字段就是这么丢的。
   - `records`（>20 条）：原样输出 `file_tag`，让用户点开右侧交互表格（可搜索/排序/翻页），
     再补一两句结论（条数、时段）。
   - `export`：原样输出 `file_tag`（xlsx 下载卡）。
3. 返回里 `rows=0` 时**必须原样转述 `note`**：
   - 有 `outside_window` → 说明「消息收到了，但事件发生在 <时间>（<班次>），属补录的更早事件」，
     并告诉用户可指定 `start=<日期>` 再查；**禁止**只说「没有」。
   - 没有 `note` 里的补录信息 → 才说本期没有通报（机器人未进群时进群前的历史消息拉不到）。
   - **禁止**因此推断「机器人收不到消息」「飞书连接断了」——那是你无法验证的结论。

**Excel 只在用户明确要时出**：说「查一下 / 统计一下 / 事件统计表 / 表格」都按默认（文字），
只有明确说「导出 / Excel / 给个文件 / 下载」才传 `export_excel=true`。

## 参数

| 参数 | 含义 |
|------|------|
| `shift` | `current`（默认，当前班次）/ `last`（最近一个已结束的班次，问「上一班」）/ `yesterday`（昨天白班+晚班 = 昨天 08:30 ~ 今天 08:30）/ `day`（白班 08:30–17:30）/ `night`（晚班 17:30–次日 08:30） |
| `date` | `YYYY-MM-DD`。**只传 `date`（`shift` 留空）= 该日白班+晚班**（08:30 ~ 次日 08:30）；配 `shift=day\|night` 才变成单班（不配 date = 最近一次已开始的该班次） |
| `start` / `end` | **只用于用户明确给出日期区间**（如「10 月 20 日到 22 日」）：`YYYY-MM-DD`（自然日，含首尾）或 `YYYY-MM-DD HH:MM`。不能与 `shift`/`date` 同时传 |
| `parks` | 园区名，逗号分隔（如「廊坊」「廊坊,平湖」）。留空 = **所有已配置园区合并成一张表**；返回里带 `skipped_parks` 时说明哪些园区群还没配置、未纳入 |
| `sync` | 默认 true：先从飞书群补拉该窗口的通报并补匹配；只想按已入库数据取数时传 false |
| `export_excel` | 默认 false。仅用户明确要 Excel/文件/导出时传 true |

**口径是班次，不是自然日**：白班 08:30–17:30、晚班 17:30–次日 08:30（00:00–08:30 仍算前一晚班）。
用户追问的某个时刻不在本次窗口内时（如「00:35 那条为什么没有」），按返回的 `window_note`
说明它属于哪一班、该用哪个 `shift`/`date` 再查，**不要说成「数据丢失」或「平台没收到」**。
**用户只给日期或星期（「本周五」「11 月 6 日」）时不要替他挑班次**：只传 `date`、`shift` 留空，
返回该日白班+晚班；只有用户明说「白班 / 晚班 / 夜班」才配 `shift=day|night`。
值守就是按班次记录告警工单，所以：

| 用户说 | 传参 |
|--------|------|
| 「查一下 / 看下现在的 / 刚发的那条」 | 留空（当前班次） |
| 「今天的事件统计表」 | `shift=current`（或留空） |
| 「昨天的事件统计表」 | `shift=yesterday` |
| 「本周五的事件统计」「11 月 6 日的事件统计」 | `date=2026-11-06`（`shift` 留空，白班+晚班） |
| 「昨天白班 / 今天白班」 | `shift=day, date=2026-10-21`（date=那一天） |
| 「昨晚 / 昨晚夜班」 | `shift=night, date=2026-10-21` |
| 「上一班 / 前一班」 | `shift=last` |
| 「10 月 20 日到 22 日」 | `start=2026-10-20, end=2026-10-22`（自然日） |

**不要**自己换算时区、班次时刻或自然周——算错了用户会看到空表。结果里的 `window` 写明具体区间与班次。

## 单个事件的进展全记录

用户问「**某个事件**的进展全记录 / 完整进展 / 处置时间线 / 后来怎么处理的」时，用
`incident_progress(query, date, start, end, parks, refresh)`，**不要**用 `incident_report`
出整张统计表代替。

- **窗口是自然日**（不是班次）：`date=YYYY-MM-DD` 查该日整天；不传 = 今天；
  区间用 `start`/`end`（规则同 `incident_report`，end 留空 = start 起 7 天）。
- `query` 写事件关键词（事件名称/地点/设备/测点，空格或逗号分隔 = **全部命中**），
  如「A2 UPS」「A18 湿度」。**不要**把整句话塞进去。
- 按返回 `mode` 交付：
  - `inline`：唯一命中 —— `progress` 是服务端渲染的「序号 / 通报时间 / 进展描述」时间线，
    `table_markdown` + `file_tag` **原样输出**；`final` 是「事件结束」段的
    处理结果/事件原因/填写人，作为结论。
  - `records`：进展超过 20 条，原样输出 `file_tag` 打开交互表格。
  - `candidates`：命中 0 起或多起 —— **原样输出候选 `table_markdown` 并问用户是哪一起**
    （可提示补充具体时刻或更精确的名称），**禁止自己挑一个**。
  - `empty`：该窗口内没有事件，按 `note` 建议换个日期再查。
- 正文来自飞书卡片原件（卡片原地追加的 `进展同步N`），平台按编号排序、同号取后出现者；
  没有编号块时才回退旧格式 `【进展描述】`。
- `refresh=true`（默认）会先补捞近 24 小时的卡片正文；更早的日期按库里已存的原文返回。

## 口径（回答用户时照此解释）

- **一行 = 一次已通报事件**：同一事件的速报 + 通报（现场也叫首报）配对成一行；匹配不到告警的通报
  **也出行**（用报文自身的发生时间/事件概述填列），不丢数据。
- **只统计配置的园区群**：`INCIDENT_FEISHU_PARK_CHATS` 登记的那些群，默认**全部合并成一张表**
  （不按园区分开）；同园区的测试群、自检合成数据不会进表。某个园区的群还没进群/没登记时，
  它会出现在 `skipped_parks` 里 —— 如实转述「该园区暂未纳入」，不要把它说成「本期没有事件」。
- **发生时间**优先取匹配到的告警触发时刻；无告警时取通报里的【发生时间】。
- **统计期按发生时间归属**，不是按消息发送时间：早上补发的昨夜事件算**前一晚班**，
  不会进今天白班；用户要查它得指定日期（`date=2026-10-25`，或 `shift=night, date=2026-10-24`）。
- **事件名称** = 地点 + 设备 + 测点 + 告警名称（无告警时用报文【事件概述】）；
  **事件类型** = 告警名称（无告警时用报文【事件类型】或规则分类）。
- **华为 eWatch 告警推送**（`【华为】<eWatch><告警产生>` 这类）也按**速报**统计；
  只有「告警产生」算，`<告警恢复>` 不算（不进行）；
  它的字段不是【】标签，取不到事件名称/类型 → 这两列留空，明文放在末尾「速报内容」「首报内容」列，
  回答时照该列说明发生了什么，**不要自己给它编一个事件名称**。
- **事件原因 / 事件进展 / 处理结果 / 处理时长**来自告警处置工单；工单还没推送到时这些列为空，
  属正常，不要说"数据不可得"。
- **过程有无违规**：速报 ≤ 发生 + 2 分钟、首报 ≤ 发生 + 5 分钟；超出会逐行写明「速报超时X分Y秒」。
- **事件等级 / 专业 / 是否完成 / 实时跟踪人员 / 经手人**留空：业务事件等级表尚未接入，
  `事件汇总` Sheet 的 I0–I4 因此全 0，结构先立住。

## 边界

- 只能读**机器人已加入**的飞书群；进群前的历史消息大概率拉不到，回填起点以进群时间为准。
- 默认查询（`parks` 留空）会**跳过**未配置群的园区并在 `skipped_parks` 里列出，不报错；
  只有用户**点名**某个园区、而该园区群没登记/没进群时才返回错误（不静默丢数据）。
- 只要有数据就同时给交互表格（≤20 条另有文字表），统计期为空时才不产文件、按返回的 `note`
  说明原因（有明显落在其它班次的补录通报时要给出可查日期），不能只回一句「本期无通报」。
- 只有 `export_excel=true` 才产出 22 列 xlsx（`事件汇总` Sheet 按园区 × 等级汇总）。
- 不要用 `analysis_load` / `analysis_exec` 重算这张表，也不要把后端返回的统计值改写。
