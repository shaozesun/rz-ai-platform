# 文档保格式翻译

把用户上传的 Word / PPT 翻译成目标语言，**保留原文件的一切**：图片、流程图、目录、表格、
页眉页脚、样式、字号——**只替换文字**。

## 🔴 铁律：原地改，绝不重建

**不要**用 `Document()`（docx）或 `Presentation()`（pptx）**新建**一份再往里填内容。

2026-09 实测：一份 **106 段 / 4 个表格 / 2 张图 / 带目录域**的中文原件，用 `Document()`
重建后变成 **52 段 / 1 个表格 / 0 张图 / 无目录**，正文还漏了一半——图片、流程图、
目录、页眉页脚、表格结构、样式全没了。用户一眼就能看出来。

正确做法：**复制原文件 → 只改文字 → 另存为新文件**。

## 本技能为什么稳（脚本实现在 XML 层）

脚本走的是 **docx 包（zip）+ 直接改 XML 文本节点**，和 Anthropic 官方 `docx` 技能
（`unzip → merge_runs.py → 改 word/document.xml → zip`）同一套思路：
**clone and modify, never recreate**。

| 对象模型（python-docx）的坑 | XML 层为什么没这个问题 |
|---|---|
| `doc.paragraphs` 看不到 `w:sdt` → **整份目录抽不到** | `root.iter(w:p)` 覆盖 sdt / 文本框 / 表格 |
| `run.text = x` 清空 run 全部内容 → **连带删掉图片/流程图** | 只改 `w:t` 文本节点，不碰 `w:r` |
| `id(element)` 去重（lxml 代理 GC 后 id 复用）→ 误跳整张表 | 按 part + 段落下标定位，不做 id 去重 |
| apply 按「第 N 个非空段落」硬写 → **静默串位** | 每段先校验原文一致，不符即整体中止、不产文件 |

**2026-09 事故复盘**：旧版 apply 按「第 N 个非空段落」硬写。那份 `segments.json` 是**旧遍历**
抽的（112 条），apply 跑的是**新遍历**（129 条）→ 编号错位 → 正文和小标题整体串位；
因为**不校验、错位是静默的**，模型连出 8 个版本都没察觉。现在的 apply 会直接报错：
「segments 与当前文档对不上」/「N 段与 segments 对不上」→ **不产出任何文件**。

## 流程（三段式，脚本已固化，照调即可）

沙箱**禁网**，脚本不能调翻译 API——所以翻译由**你**做，脚本只负责"抽文本"和"写回去"。
沙箱也**禁 subprocess**，脚本不能用命令行参数跑：它读**工作区里的任务文件**
`doc_translate_task.json`（你写任务文件 → 调脚本，这样循环）。

1. **原件放进工作区**：`copy_uploaded_file_to_workspace(filename='原件.docx')`
2. **脚本就位**：`stage_skill_script(skill='doc_translate', script='doc_translate.py')`
   → 工作区出现 `doc_translate_doc_translate.py`（下称 `<脚本>`）
3. **抽取**：写任务文件 `{"cmd":"extract","src":"原件.docx","out":"segments.json"}`
   （用 `analysis_write_file(dataset_id='workspace', path='doc_translate_task.json', content=...)`）
   → `analysis_exec(dataset_id='workspace', file='<脚本>')`
4. **取待翻译文本**（分页，防 stdout 截断）：任务文件改成
   `{"cmd":"show","out":"segments.json","from":1,"to":60}` → 再跑 `<脚本>` → 你看到 `编号\t原文`
   （长文档就 1-60、61-120… 分批取）
5. **翻译**：逐段翻，写成 `{"1":"译文","2":"译文",...}` 落盘为 `translation.json`
   （分批时把多批译文合并成**一个** translation.json 再一次 apply）
6. **写回**：任务文件改成
   `{"cmd":"apply","src":"原件.docx","seg":"segments.json","trans":"translation.json","dst":"English.docx","clean_cjk_indent":true}`
   → 再跑 `<脚本>`
7. **交付**：按返回的 artifacts 输出一行 `<file url="..." name="..."/>`（url 逐字复制）

**`seg` 必须指向本次 extract 产出的那个 segments.json**——它是 apply 的校验依据，
换文件 / 用上一次的都会让 apply 报错（这正是设计目的，不是 bug）。

## 必须遵守的坑（踩过的）

- **按段翻，不要按 run 翻**：Word 会把一句话切成多个 run（拼写检查、格式边界）。
  脚本已按段落（含表格单元格、页眉页脚）抽好并编号，照着编号翻即可。
- **每段都要给译文**：脚本会报「未给译文而保留原文 N 段」。**N 不为 0 就补齐重跑**——
  漏段是这个问题里最常见的失败。
- **中→英时带 `clean_cjk_indent: true`**：中文段落的「首行缩进 2 字符」在英文段落里是多余的
  （脚本会一并清掉；只清这一类属性，真实缩进不动）。
- **不要动源文件**：脚本另存为 `dst`，原件保持原样；`dst` 落在 workspace 会被扫成可下载卡片。
- **apply 报错就是报错，不要绕**：报「segments 已过期 / 段数不符 / 第 N 段对不上」时，
  正确动作是**重新 extract + 重新翻译**，**不要**去改 segments.json 或让脚本忽略校验
  （那正是上次串位的成因）。
- **翻完检查排版**：英文通常比中文长 1.5~2 倍，PPT 文本框可能溢出、段落可能多折行。
  逐页/逐段看一眼，有问题如实说明（必要时提示用户手动微调字号）。

## 抽取覆盖到哪、没覆盖到哪（如实告知用户）

**已覆盖（会翻）**：正文段落、**表格单元格**（含嵌套表）、**文本框**、**内容控件 `w:sdt`**
里的段落、页眉、页脚，以及**脚注 / 尾注 / 批注**（独立 part，脚本现在也走）。

**故意不翻（域内容，回复里必须告诉用户）**：
- **目录条目 / 页码 / 日期 / 交叉引用**——凡是段落里带 `w:fldChar` / `w:fldSimple` /
  `w:instrText` 的域，**整段保持原文**。原因：它们是 Word 自动生成的，静态改写会把页码写死或
  写乱；而且域内文本连着页码（抽取出来是 `1.1编写目的1`），照翻必然失真。
  **正确做法：告诉用户「英文目录请在 Word 里选中目录按 F9 更新」**（页码会按译文重排）。
  extract 会打印「跳过 N 段自动生成内容」，把这个 N 如实报给用户。
- 典型受影响处：目录页、页脚「第 X 页 共 Y 页」（页眉里的文档标题**会**翻）。

**翻不了（脚本不碰，回复里要说明）**：
- 图片里的文字、流程图里的文字、SmartArt 内部文字、图表数据标签；
- 母版/版式里的静态文字（PPT）。

判断方法：`extract` 后看段数与来源统计是否合理（脚本会打印每个 part 的段数）；
有疑问就把原件的结构概要（`read_uploaded_file` 返回的 `structure`）和抽取段数对一下。

## 残留在产物上的已知取舍

- **段内混合格式**（如句中某个加粗的词）：译文会退化成该段**首个文字 run** 的格式。
  单格式段落（绝大多数）完全无损。若某段原文确实含多种格式，如实说明。
- 产物版式与原件的页数一致（可用 `render_check` 转 PDF 核）；但英文更长，个别段落可能多折行。

## 什么时候不要用本技能

- 用户**没有**源文档、从零要一份报告 → 用 `Document()` 新建（另一条路，见系统提示的报告生成规范）。
- 只是问文档里写了什么 → 用 `read_uploaded_file`，不要产文件。
- **PPT（`.pptx`）尚未支持**：本技能目前只处理 `.docx`。用户要翻 PPT 时**如实说明暂时做不到**，
  不要退回「用 `Presentation()` 重建」——那会把母版/版式/图片全丢掉，比不翻更糟。
