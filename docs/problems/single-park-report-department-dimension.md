# 园区级报告：为什么用「部门」维度补位（2026-10-29）

## 结论

园区级变更单报告（`change__{园区}__weekly|monthly`）的第 5 章由「园区横向对比」改为
**部门横向对比**：部门哑铃图（本期 vs 上一期）+ 部门效率表；第 8 章补「各环节耗时」
「分等级时效」，异常单表补「占比」。**全国级报告一个字不动**（新统计键只在单园区写入）。

## 问题

用户看完园区级周报（廊坊，105 单）后问「园区单独的分析报告为什么没有各部门的分析角度」。核对发现：

- 单园区预设传 `company_id=<pen kingdee>`，**不传 `all_companies`** → 列表返回的每条记录
  **不带 `companyName` 列**（该列只有全国聚合时由 `client._aggregate_companies` 逐条补）。
- 于是 `stats['park']` 为空 → 第 5 章只剩一句「本次统计范围为单个园区」，
  `park` / `park_level` / `on_time_by_park` / `park_specialty` 四张图全部退化成
  「图 N（…）本次无可用数据，未生成」的占位。**一整章 + 四张图是空的。**
- 而 `dc`（部门，客户端已把 id 换成中文名）**一直就在数据里**，此前只被
  「审批最慢部门」用到 —— 它是**园区内部唯一可比的横向维度**。

## 落地

| 层 | 改动 |
|----|------|
| 统计 | `change_compute._dept_block` / `_flow_durations` / `_by_level_duration`，只在 `'companyName' not in cur.columns` 时写入 `stats['dept']` 与 `flow` 的三个键 |
| 规格 | `Chart.requires_key`（默认空，其余四类行为不变）；四张园区图声明 `'park'`、两张新图声明 `'dept'`；新图**追加在 `spec.charts` 末尾**（既有图号 00~11 不能漂移） |
| 渲染 | `_Ctx.chart` 按 `requires_key` 跳过无数据的图（**不出图、也不留占位**）；`_r_park` 单园区分支改用部门表；`_r_flow` 追加两张表 |
| 事实/解读 | `facts` 与 `narrate` 的 `park`/`flow` 分支补对应块；brief 明确「本章部门数据只在单园区报告出现」 |

## 口径边界（写进报告，别改口径）

- **按时率 / 紧急占比 / 驳回率的分母**是该部门**本期单量**（驳回还含 `stage == -1`）。
- **P50 样本 <3 单显示「—」**：两单算分位没有意义。
- **各环节口径不同、不可相加**；`全流程 = createTime → executeEndTime`，
  **关闭期没有时间戳**，所以三段之和不等于全流程（中间的空闲与等待期未计入）。
- **驳回/撤回/退回/延期中是当前状态快照**，不是流转史，同一张单可能落在多类里。
- **不做的三项**（数据不支持，写进第 13 章 `unavailable`）：变更引发的事件（缺关联工单号，
  **需与事件工单联动后补充**）、重复变更（缺设备标识）、关闭期耗时（缺关闭时间戳）。
- **不做人均变更量**：需要额外的人员编制接口（用户已明确排除）。

## 顺带的两处修正

1. **散点线性 + 默认宽画布（先嫌扁、后嫌方）**：第 9 章「计划 vs 实际实施时长」原为双对数
   （理由是时长跨 3 个数量级），用户要求改回线性 —— 跨数量级不是让读者理解坐标轴的理由。
   线性轴上改用 `_duration_ticks` 的友好阶梯（1 分钟 ~ 30 天，最多 7 个刻度）+
   `_human_minutes` 标签。第一版为保住 45° 对角线改成 7.2×7.2 + `set_aspect('equal')`，
   用户随后反馈「太方了」—— **`set_aspect('equal')` 配 `savefig(bbox_inches='tight')`
   保存出来必然是正方形，只改 figsize 无效**。最终＝回 `plt.subplots()` 默认宽画布、
   **不设 aspect**；参考线仍画 `[0, hi]` 对角线，但不再强制 45°。
2. **不再出现空图占位**：`requires_key` 门控让「维度不存在」和「数据缺失」区别开 ——
   前者不出图，后者才印「未生成」。

## 2026-10-29 第二轮：削减重复统计

用户看完重出的园区级周报（30 页）后说「重复的指标统计就不要重复显示了，现在有点统计
过头了吧，你先好好查一下」。逐表核对生成 HTML 后确认的重复清单与处置：

| 指标 | 重复位置 | 处置 |
|------|---------|------|
| 审批/验收 P50·P90·P95 | 第 8 章「审批与验收」表 ↔「各环节耗时」表 | **删前者**，只把最易丢的「超时」留成一行 note |
| 分等级 审批/实施/验收 P50 | 图 13 ↔ 第 8 章「分等级时效」表（9 个数一字不差） | **删表**，留图 |
| 部门单数 + 审批 P50 | 第 5 章部门表 ↔ 第 8 章「审批最慢部门」 | **删后者** |
| 紧急占比/按时率/驳回率 | 第 5 章部门表 3 列，分别与第 7/8/9 章同源 | **删这 3 列**（表 10 列 → 7 列） |
| 阶段表 vs 状态表 | 第 8 章两张表的数字一一对应（同一批单两个视角） | **合并成一张联合表** |

**保留与边界**：

- **统计层一个键都没删**：`_dept_block` 仍算 emergency/on_time/reject（自检依赖其分母
  口径）、`flow['stage']`/`flow['status']` 两个边际列表仍在（自检与归因切片用）、
  `slowest_dept`/`by_level_duration` 仍在（解读仍需要）。只收窄**显示与下发**。
- **图 + 表同源（第 3/4/7/9 章）与 KPI 卡片：用户未选，本轮不动。**
- 阶段/状态联合表必须**按 `(stage, status)` 真 groupby**，不能按标签静态配对 ——
  状态 9「延期中」与阶段正交（审批期的单也可能延期中）。新函数
  `change_compute._stage_status_rows`，统计键 `flow['stage_status']`（按单量降序、
  同量按码值排序，保证跨期稳定）。
- 顺带删掉两处死代码：`render._duration_rows`（随「审批与验收」表一起无用）、
  `narrate._dept_view`（随「最慢部门」键一起无用）。

**图表尺寸**（同轮）：`12_dept` 与 `13_stage_duration` 的 figsize 从「随行数线性增长」
（8.6 in / 3.3 in，宽高比 0.97 / 2.88）改为 `min(6.0, max(4.8, …))`，与常规图
（8.2×5.2，1.60）同量级；16 个部门取 6.0（1.37）、3 档等级取 4.8（1.73）。
高图里图例的轴坐标偏移会被放大成整条空白带，故 `12_dept` 用 `y=-0.12`
（−0.06 会与 x 轴标题「工单量」挤在同一行）。
