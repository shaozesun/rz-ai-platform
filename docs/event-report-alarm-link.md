# 事件报告：重复类目关联 DCIM 告警（告警值 + 四档阈值）

> 需求（用户 2026-10-30）：事件报告里的**高频重复事件**要查出关联告警，展示当时的**告警值**
> 与该点位的**告警阈值**情况。
> 实现（2026-10-31）：`service/scheduled_task/report/alarm_link.py`，挂第 7 章「高频高发问题根因分析」
> 的每个重复类目之下。纯服务端逻辑，不进 Agent，**失败只记日志，不让报告失败**。

---

## 一、已定口径

| 项 | 口径 |
|----|------|
| 关联范围 | **只关联重复类目**：`stats['repeat']`（同一 `projectName` 出现 ≥2 次） |
| 搜索方式 | **该类每一次发生各搜一次**（代表单先搜；其余发生先复用代表单命中的点位签名） |
| 多候选 | 时间窗内多条告警时**由模型仲裁**（地点/设备/测点/事件名称语义，**不要求字面完全相同**）；判不出留空 |
| 展示位置 | 第 7 章重复类目表下，每个类目挂一张子表 |
| 展示内容 | 时间 / 等级 / 设备·测点 / 告警内容 / **告警值** / **提示·一般·重要·紧急四档阈值全印** / 越限档 |
| 等级与排序 | **全部等级**，按等级（紧急 → 提示）+ 时间升序；**不截断** |

「代表单」= `stats['repeat'][i]['ticketNo']` 对应的记录（`common._repeat_problems` 已按票号排序取第一条，
口径稳定）；取不到票号时退回该类最早 `occurrenceTime` 的一条。**代表单先搜，其余每一次发生也要搜**
（2026-11-02 用户要求「其他发生的告警时间与告警值也要显示，不是只取一条」）：

- 发生的取法 `_occurrences()`：`projectName` **去首尾空白后字面相等**（与 `_repeat_problems` 的计数口径
  同源，不做标点归一，否则 `total` 会与 `count` 打架），按 `(ticketNo, 发生时间秒)` 去重，
  代表单排第一、其余按发生时间升序。
- **点位签名复用**：代表单命中告警后记下 `(cluster, device_guid, point_guid)`；其余发生的窗口里
  若存在同签名的告警 → **确定性选中**（多条取时间最近），`match='point'`、**不调模型**。
  这是让「同一测点反复告警」的多条记录稳定对上的关键，也避免为每次发生各付一次仲裁。

## 二、为什么只能启发式匹配

事件单（列表 + 详情）**没有任何设备 / 点位 / guid 字段**。可用的只有：

- 列表：`occurrenceTime`（毫秒 epoch）、`companyName`（仅全国口径）、`dc`（部门/机房）、`projectName`、`ticketNo`、`level`、`specialty`
- 详情：`事件名称` / `事件描述`（`_DETAIL_FIELDS['mgmt.query_event_ticket_detail']`）

⚠️ **两个口径坑（2026-11-02 生产实测，已修）**：

- `dcim_alarms.cluster` 存的是**带园区前缀**的代号（`廊坊A` / `廊坊B1M1` / `廊坊B1M2`），
  不是 `A` / `B1M1` / `B1M2`。按短码传 `= ANY` **恒不命中**（当时的诊断：全国/园区报告候选数均为 0）。
- 全国口径的 `companyName` 是**法人主体**（`润泽科技发展有限公司` / `广东润惠科技发展有限公司`…），
  不含「廊坊」。判园区要经 mgmt 公司档案的 `gardenName`（`廊坊园区` / `佛山园区`…）换一次。

而 DCIM 告警是按**测点**推的。两者的唯一强信号是**时间**，其次是地点与文本语义。
因此设计原则是 **「不配优于配错」**：宁可留空，也不硬配一条无关告警。

## 三、匹配流程（确定性收敛 → 模型仲裁）

**全部重复类目**（不设类目数上限）：

1. **门控**：`settings.DCIM_ENABLED` 且 `DCIM_PG_DSN` 非空；统计期末 < `ALARM_COVERAGE_START` 直接返回
   `available=False` + 覆盖说明。
2. **园区收敛**：园区级报告以预设的 `park` 为准；全国口径先看 `companyName` 里是否含「廊坊」，
   否则经 mgmt 公司档案（`company_registry()`，Redis 缓存）把法人主体换成 `gardenName` 再判
   （**只在确有类目需要时才查**，取不到只记 warning）。非廊坊 → 不查询、记「DCIM 告警未覆盖」；
   园区未知 → 记「无法确定所属园区」，**不猜**。兜底只看 `dc` / 类目名里的集群代号，
   且只认 `B1M1` / `B1M2` 这类无歧义码，`A18` 这种跨园区歧义码不猜。
3. **时间窗**：**每一次发生**的 `occurrenceTime` 各自转秒，在 `dcim_alarms` 上取
   `alarm_time ∈ ts ± 120s`，走 `(cluster, alarm_time)` 索引点查（`status='all'`，`limit=200`）。
   代表单先查，其余发生按发生时间顺序逐个查（各一次索引点查）。
4. **机房码收敛**：从 `dc` 与类目名里抽 `[A-Z]\d+(?:M\d+)?`（如 `A1`、`B1M2`），只保留 `space_name`
   含该码的候选；**命中 0 条时退回未过滤集合**（不因抽错码丢掉全部候选）。
5. **文本排序**：字符二元组 Dice（类目名 + 有详情时的 `事件描述` vs 告警
   `设备+测点+内容+空间名`）降序取前 `LLM_MAX_CANDS`=8；若时间最近那条不在前列则补进去
   （它常常文本最不像、但时间完全对上）。
6. **决策（逐次发生各自判）**：
   - 已有点位签名且候选里有同签名 → **确定性选中**（多条取时间最近，`match='point'`，不调模型）；
   - 候选 0 条 → 该次未匹配（逐次记理由）；候选 1 条 → **直接接受**（`match='time'`）；
   - **候选 ≥2 条 → 模型仲裁**（`match='llm'`）：返回候选序号则接受，`null` / 超时 / 越界 / 异常一律未匹配；
   - 代表单那次**额外学签名**（命中告警后），供其余发生复用；
   - **每次歧义发生各自一次仲裁**，不设全局次数上限（单次仍受 `LLM_MAX_CANDS`=8 与 15s 超时约束）；
     实际调用次数通常远小于发生数，因为签名命中的发生不调模型。
7. **输出排序**：全部命中的告警按 `(cluster, event_log_id)` 去重后，等级降序（紧急 → 提示），
   同级按告警时间升序。

仲裁是一次**独立的 `model_gateway.chat` 调用**（`caller='event_alarm_link'`，`temperature=0`，
`max_tokens≈300`，`json_mode=True`，`timeout=15`），返回 `{"pick": <序号|null>, "reason": "…"}`；
`reason` 只进日志/内部字段。**不经 Agent 链路**（同 `incident_stats/arbitrate.py` 的形态），失败 fail-open 到「未匹配」。

## 四、告警值：必须取触发时刻

当前态表 `dcim_alarms` 是**三态 upsert**（触发 1 / 刷新 2 / 恢复 3），同一 `guid` 只有一行，
`alarm_value` / `alarm_time` 会被刷新/恢复推送**覆盖**。因此：

- 触发值走 `dcim_alarms_history`：按 `(cluster, guid)` 精确取，第一条 `payload->>'status'='1'` 的 `value`；
- 取不到（历史缺失）才回退当前态 `alarm_value`，并标 `value_from='current'`；
- 都没有则 `value_from='missing'`，渲染为 `—`。

⚠️ 历史表**没有时间索引**，故只做 `(cluster, guid)` 精确查询，**不做时间范围过滤**（全表扫描会拖垮报告）。

## 五、阈值语义（四档全印）

阈值来自 `dcim_points` 的 `hint_alarm` / `general_alarm` / `important_alarm` / `urgent_alarm`
（+ `unit`），每个是一段 JSONB，含 `maxUse`/`maxAlarm`/`minUse`/`minAlarm`。

⚠️ **查询键口径（2026-11-02 缺陷修复，别退回短码）**：`dcim_alarms.point_guid` 存的是**测点代号**
（`PDU_I09`），而 `dcim_points.guid` 是 `device_guid + '.' + 测点代号`
（`CHNLFB01-…-0000M2402002.PDU_I09`）。直接拿 `point_guid` 去 `WHERE guid = ANY(...)` **恒 0 行**
→ 四档阈值全 `—`、单位为空。查询前用 `_point_key()` 拼全键（已是全键或缺设备号时原样）。
抽样核对：按拼接键查**3000/3000** 条告警都能命中。

- **判据是 `maxUse` / `minUse`（开关字段），不是 `maxAlarm != 0`**：
  通断类测点 `maxUse:1, maxAlarm:0` 里那个 0 是**真上限**（如「合位 = 0」），按数值非零判断会漏掉。
  语义唯一来源：`service/query/dcim_meta/client.py` 的 `_enabled` / `_breach`（本模块内复刻并在注释里指回）。
- 某档双边都未配置 → `None`，渲染 `—`；单边配置 → `高于 30` / `低于 10`；双边 → `低于 10 或 高于 30`。
- ⚠️ **列里印的是「告警触发条件」，不是正常取值范围**：`maxUse`/`minUse` 是开关，
  `maxAlarm`/`minAlarm` 是触发点。例如 `urgent_alarm {minUse:1,minAlarm:0.01,maxUse:1,maxAlarm:32}`
  表示「低于 0.01 或 高于 32 才告警」。2026-11-02 用户纠正：原先把两个触发点写成区间 `0.01~32`，读起来像正常范围。
- **越限档**：用触发值逐档 `_breach`，可命中多档时按**重 → 轻**全列（如「紧急、重要」）。
  ⚠️ 这是**展示口径**，不是平台告警判定的替代——真实告警档位以后端推送为准，这里只做可复核的自洽性检查。
- 实现注意：`_breached_tiers` 按**列名**（`hint_alarm` …）取阈值，必须传 `dcim_points` 的**原始行**，
  不能传已按中文档位建好的 dict（2026-11-02 修：此前传错参数，越限档**永远为空**）。

## 六、覆盖范围（决定「能不能关联到」）

| 项 | 值 |
|----|----|
| 园区 | 仅**廊坊** |
| 集群（查询值） | `廊坊A` / `廊坊B1M1` / `廊坊B1M2`（库里就是带前缀的代号） |
| 集群（代号后缀） | `A` / `B1M1` / `B1M2`（用于机房码 / 部门名比对） |
| 数据起点 | **2026-10-29**（实测库里最早 2026-10-26 02:31，常量仍取保守值） |

→ 7–9 月的历史报告、其他园区（平湖/惠州/佛山/重庆）的事件，**永远关联不到**，
只出覆盖说明，不出子表。**「未关联到」≠「没有告警」**：解读层 brief 明确禁止这样推断，
覆盖范围由平台在 `note` 里如实给出。

## 七、产出形态

`workflow.py` 在 `details['highlights']` 之后、`narrate(...)` 之前挂 `details['alarm_links']`：

```python
{'available': True, 'reason': '',
 'clusters': [
   {'name': '<类目名>', 'count': 4, 'total': 4, 'matched_n': 3,
    'occurrence': {'ticketNo': '...', 'occurred_at': '2026-11-02 14:03',
                   'dc': 'A1分部', 'match': 'time'|'llm'|'point'|'', 'reason': '<仅日志>'},
    'occurrences': [{'ticketNo', 'occurred_at', 'dc', 'match', 'reason'}, ...],  # 每一次发生
    'alarms': [{时间/等级/设备/测点/内容/告警值/unit/
                thresholds: {'提示': [lo, hi]|None, ...}, breached: ['重要'],
                value_from: 'trigger'}]}],
 'linked_n': 25, 'llm_calls': 8, 'cache_hits': 0,
 'note': '未关联到告警不等于没有告警：…'}
```

- `total` = 本次参与匹配的发生数（同一 `ticketNo` + 同一发生时刻的重复报单只算一次）；
  `matched_n` = 至少命中一条告警的发生数。`occurrences` 逐次记录命中信号，排障看日志。
  **渲染的「共 N 次发生」沿用类目表的 `count`（工单行数）**，避免同一页出现「（6 次）」与
  「5 次」两种说法；`matched_n` 仍按发生数计，`matched_n >= count` 才写「均关联到」。

- **渲染**（`render._r_repeat` → `_alarm_link_block`）：事件报告**正文只留一句跳转**
  （「本期识别到 N 类重复问题，其中 M 类关联到 DCIM 告警。完整清单与关联告警见
  附录「重复问题与关联告警」」），全量重复类目表 + 告警子表整体放进
  `<div class="section appendix" id="sec-repeat-appendix">`（由 `EVENT_SPEC.repeat_appendix`
  门控，其他报告仍原地渲染；目录同步多一条无编号条目，PDF 侧栏有书签）。
  子表列 `时间 | 等级 | 设备 / 测点 | 告警内容 | 告警值 | 提示 | 一般 | 重要 | 紧急 | 越限档`；
  **关联上的类目全部出子表、告警逐条全列**（`MAX_ROWS` 截断已于 2026-11-02 删除，不再有
  「另有 N 条告警未列出」），告警内容截 40 字；表下附一句
  「本期该类共 {count} 次发生，其中 {matched_n} 次关联到 DCIM 告警」（`matched_n >= count` 时写
  「均关联到」；`count` 与标题「（N 次）」同一口径，重复报单不会让同页出现两个数字）；
  未匹配类目出一行 note，全空只出一行覆盖说明，**不出空表**。
- **解读**（`narrate._alarm_link_view`）：每类下发 `{名称, 次数, 代表单, 关联次数(matched_n/total),
  关联条数, 告警(时间/等级/设备测点/告警值/越限档)}`（告警不再切片），
  **不下发整张阈值表**；brief 允许引用告警证据（哪类重复事件对应哪类告警、越了哪档），
  **不得换算单位、不做四则运算**；未匹配须如实写「未关联到 DCIM 告警」，**不得推断为没有告警**。

### 判定表复用（`alarm_decision.py`）

匹配结论**逐次发生**落在判定表（Mongo `event_alarm_link_decisions`，一行 = 一次发生，
键 = 工单号 + 发生时间 + 口径），报告与对话共用：命中即跳过点查与仲裁，缺失才补判并写回。
状态机、重查策略、版本失效与对话工具的完整说明见
[`problems/event-alarm-decision-table.md`](problems/event-alarm-decision-table.md)。

旧的「结论快照缓存」（`alarm_cache.py` / 集合 `event_alarm_links`，键 = 代表单号 + 类目名）
已于 2026-11-09 停用：**不读、不删、不迁移**（历史留档）。它粒度太粗、键里没有口径维度
（W45 全国报告的「非廊坊」结论被廊坊园区报告原样命中，导致廊坊一条告警都没关联），
且只存展示快照、无法追溯或刷新告警身份。

## 八、失败隔离

- 整轮异常（连接/查询失败）→ `logger.warning` + `available=False` + `reason`，**报告照出**；
- 单类目模型仲裁异常 → 该类未匹配，其余类目继续；
- 关闭连接失败只 `logger.debug`；
- 不新增任何 LLM 调用到统计层；`stats` / `facts` / `charts` 完全不变（子表由 `details` 驱动，e2e 不跑 DB 链路）。

## 十、边界与已知盲区

- **逐次发生都要搜**（2026-11-02 起）：代价是每类按**发生次数**点查（W44 廊坊约 65 次、
  全国约 112 次，均为 `(cluster, alarm_time)` 索引点查），每个「无签名且 ≥2 候选」的发生各一次
  仲裁 —— 比原来多出几十秒，属用户要求的完整性代价。
- **签名只来自代表单**：代表单若没配对（候选 0 条 / 仲裁判不出），其余发生就没有签名可复用，
  只能各自走「单候选直接接受 / 多候选仲裁」。同一测点重复告警时通常仍能稳定对上。
- **匹配质量依赖模型与位置信息**：事件单无设备标识，确定性只能缩窗；宁可留空也不配错。
- **覆盖有限**：非廊坊园区、2026-10-29 之前的期次一律关联不到。
- **模型调用**：单次 ≤15s、`temperature=0`、每个歧义类目至多一次，**无全局次数上限**。
- **当前态表无界增长**（含已恢复）：按 `(cluster, alarm_time)` 索引点查，每次发生一次，不做全表扫描。

## 十一、真实数据校准（2026-11-02，生产库只读实测）

拿 W44（2026-10-26 ~ 11-01）两份真实报告的代表单跑「候选检索 + 机房码收敛」，**未接模型仲裁**
（用确定性「时间最近」桩），结论是**数据边界在起决定作用，不在参数**：
